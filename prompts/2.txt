Okay this is almost it, can you rework the lex.rs to produce tokens that are
    just Tok(u32)? That way, you can make a method that turns Tok(u32) into
    TokVal{enum of all the vals, basically equal to the Token type
    implemented previously}. Allow for a function that returns TokTy which
    is just returns all of the Token (rename to Tok) variants except not
    storing string/f64/bool, etc.

These 3 types: Tok, TokTy, TokVal can create a very minimal tokenizer. The
    TokTy is returned by simply looking at the first char at that byte
    offset or performing retokenization that instead returns a type
    instead of an index. Another interface func to the lexer is to return
    both a token index and a token type in a tuple. I think these can all
    live happily in the lexer, if you foresee problems let me know.
