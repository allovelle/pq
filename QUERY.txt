Every query separated by a dot is a new JSON lines document with it's own id as
the parent id.

New queries are new document roots: create visualizer that shows
all of the JSON documents being transformed with the query type
to another JSON document and then in the terminal you'll be able
to visualize all the transformations!

If a node has subnodes, transform the parent and just append the
child nodes in line to bring them with the new tree!

For example, filtering out a key means keeping some keys that
have possibly very nested subnodes. You can just iterate through
them in line without breaking anything just write them to the
same scratch space or directly to the tree if that begins to

cursor: traverse the tree using arrow keys. cursor commands are special commands
    in that they are relative to the key! so instead of a.b.c where c means b[c],
    a.b.> means the next sibling of b *within a*, meaning the next sibling within
    a relative to b. a.b.\ means first child of b. without this syntax, every
    command filters downward *within* the current object not *relative* to it.
    need special commands for:
        goto-parent: nest outward
        goto-child: nest inward
        next-sibling: move down
        prev-sibling: move up

    {foo: {bar: {baz: {name: "alo"}}}}
        foo.bar.[v,].name
        foo.[>>].name
    {foo: {bar: [1, 2, 3, 4]}}

Referent Commands & Relative Commands:
    referent commands select object keys, array indices, or perform filtering
    or data mapping operations. relative commands perform tree-traversals over
    the selected/filtered/computed resulting tree. referent commands are like
    actual commands and relative commands are like meta commands.
    Ref queries do not support

Referent Queries:
    a a.b                                   ref sel
        Select key
    (a) (a.b)                               ref sel
        Expr select nested. 'Compute' the nested keys as one expr
    (name.capitalize())                     ref cmp
        Expr map
    [0] [0:] [0::]                          ref sel
        Expr select index
    [3, 1, 2:4, 6::8]                       ref sel
        Index build array: does not support key lookup
    [len(temperatures) // 2 + 1:]           ref cmp
        Expr build array. This is both a compute and select query.
        The built elements came from the parent, even if computed.
    [temperature > 32]                      ref sel
        Expr filter (indexing by boolean doesn't make sense 👍)
    [temperature > 32, name.upper()]        ref cmp
        Expr filter map (indexing by tuple doesn't make sense 👍)
    {a,b}                                   ref sel
        Inclusive build object, no err on missing
    {-a,-b}                                 ref sel
        Exlusive build object, no err on missing
    {a,-b}                                  ref sel
        Inclusive first, no-op exclusive keys, err on missing
    {-a,b}                                  ref sel
        Exclusive first, no-op inclusive keys, err on missing
    {a, b: b + 1, "c": c}                   ref cmp
        parent effectivly undoes the compute/calculate operation
        Build object with expression handling
    {a, {b: b + 1, "c": c}}                 ref cmp
        Build object using set & nested dicts for expr parsing
Relative Queries:
    b./.b                                   rel sel
        goto parent
    \                                       rel sel
        goto child
Compute Queries:
    produces an entirely new/seperate json tree from the point of invocation.
    goto-child works as expected, goto-parent can only go to itself (the new
    root).
Select Queries:
    traverses an existing json tree while preserving lineage for parent node
    traversal.
